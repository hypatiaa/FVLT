# M4 v0.3 interfaces

The unchanged McombAtomCoreV1 and McombAtomPacketV1 APIs remain documented in M4_V02_PREDECESSOR_API.md. Their source bytes match the independently audited predecessor.

McombShellWalkV1 exposes context(h), facts(h), derive(h, options=null), construct(h, options=null, visits), replay(bytes), source(h), exponentAddress(atom,d), SCHEMA and pins. construct/replay are asynchronous because they hash the complete canonical record. context validates and parses; facts does not depend on geometry availability. derive returns input, atomRecord, certificate, selection, walk and hostSpectrum. construct adds schema, definition/predecessor pins, context, options, visits and exactDigest.

Context schema M4_HOST_SHELL_CONTEXT_V1 has shell={mode,base,factorialIndex}, position, s,t1,t2,m,amplitudeSign. Every exact scalar is a canonical reduced rational or integer string. s=null means the exact spin is unavailable. Base mode is factorial (index3..13, recomputed factorial) or integer (base 2..6227020800, null index). INTEGER_SHELL position has exact phi3,N strings. BETWEEN_SHELLS has explicitly numerical canonical phi3Display,NDisplay strings, required to be consistent but never used in an exact encounter. Comb size 1..720; amplitudeSign is -1,0 or1.

Optional orbit controls are {start,step,character,chirality}. They affect the independent atom orbit, not the fixed atom target or shell encounter. The shell layer uses SHARED_OFFSETS_ONLY, making no quotient-map assertion. Imported manual packets retain their existing binding rules.

The shell packet schema is MCOMB_ATOM_SHELL_WALK_V1. Strict field checks and the 12,000,000-byte cap apply before replay; construction checks the complete serialized size before offering export. Exact strings/booleans/structure replay exactly. Numerical observations use64*Number.EPSILON*max(1,abs(expected),abs(actual)), then fresh values are returned. No rounding of rational quantities or symbolic labels occurs. Serialized records are not signed attestations of historical visits.

Automatic factorization inherits target<=10^12 and bounded trial division. The manual core retains up to16 primes<=10^6, exponents1..64, product<=256 bits, selected orbit<=4096. Automatic unsupported targets retain exact walk facts with atomStatus=UNAVAILABLE. Full coset/address enumeration is capped at4096, graph/plot drawing at256 addresses. Character-order factorization and graph rules are unchanged. A cached atom is keyed by target, comb size and orbit controls; at most 8 caches are retained.

Visits are {dropped:nonnegativeIntegerString,entries:[contexts]}. The latest 64 observed encounter contexts are retained; repeated returns remain separate. Each must be a nonzero integral-product divisor encounter for the current atom target. Updates are sampled; no claim is made that intervening animation shells were visited or logged. Target changes reset the log. The current source and each visit preserve their own base and gearbox context.

McombShellWalkHostV1.capture() reads the host's coherent committed snapshot and exact spin availability. McombAtomAdapterV1 keeps refresh/configure/reopen/inspect/follow/snapshot/inspection/state, adds followWalk() and walkState(). configure and follow select manual mode. followWalk resumes actual viewer capture. walkState returns mode,held and the plot rebuild counter used in the browser regression. Held imports are replayed sidecar views; they do not mutate host controls. Snapshot returns null while a computation is pending or rejected. Stale asynchronous results cannot commit across a source revision or newer request.
