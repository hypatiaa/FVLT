# U1 records and trust boundaries

BSD_U1_REQUEST_V1 contains exact ainvs, marking, selectedMultiplier and the current linked/source/T4/model/normalization/marking binding. The neron flag must be rebuilt from the current signed T4 result. The public gate compares a caller-supplied expected request separately from proof contents.

BSD_REAL_UNIFORMIZATION_V1 contains the request, result, status, reason, normalization label and verifier source hashes. produce(request) creates an untrusted candidate. replay(bytes, expectedRequest) reconstructs the entire record and returns PASS, UNAVAILABLE or REJECTED. Status RIGOROUS_ENCLOSURE describes enclosed numerical quantities; it does not supply exact irrational decimal coordinates. Model periods and positive total real measures are distinguished from signed selected-differential periods.

The strict linked export wrapper is BSD_REAL_UNIFORMIZATION_LINKED_V1 with fields schema, linked, pt1, u1. Legacy PT1 wrappers remain readable. Import never accepts derived comparison state as authority. The readonly BSDUniformizationV1.snapshot() exposes no commit setter.

Every dyadic endpoint is serialized as an integer divided by 2^192. Interval displays round decimal lower bounds downward and upper bounds upward. Float64 geometry is derived display only. Basis rows transform by M; coordinate columns transform by M^(-transpose). Real-adapted component data is separate from arbitrary marked coordinates.

The immutable server, assess-stdin, T4 endpoint and T4/PT1 arithmetic engines retain their predecessor bytes. New browser-local numerical modules and the changed adapter/client/register consumer have separately pinned hashes. Replayed U1 failure cannot fabricate or revoke the independent arithmetic result; it removes U1-derived period authority.
