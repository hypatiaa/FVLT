# M4 verification and sealing

The complete default is `node verify.cjs`. It creates a new scratch tree, inventories every source and staged predecessor, discovers the declared runtimes, and executes all current viewer suites plus inherited T4/T3/T2/T1/schema arithmetic. Every mutable receipt and browser image is outside the source and staged packages. The wrapper checks those inventories again in its finally block, including failures.

The new suites are test-atom.worker.cjs and test-atom-browser.worker.cjs. Arithmetic covers A1–A10, M4-S1–S4, direct sums from the pinned extracted source for all chiralities and both comb parities, independent small orbit partitions and graph counts, symbolic zeros, tiny numerical near-coincidences, bounded refusals, binding kernels, packet replay and rehashed forgeries. Browser checks use the actual assembled viewer, including pointer and keyboard selection, each stale-state trigger, export/reopen, a delayed old result, narrow layout and preserved BSD authority boundaries.

The default also retains all prior test suites. The historical eight-check Cayley smoke suite keeps its declared PARTIAL scope. It is not relabelled as complete browser acceptance.

Before sealing, finish all source documents and run `node verify.cjs` (a full default is preferred; the seal also accepts the established v1-only pre-seal mode). Supply its external verification receipt to `node seal.cjs <receipt>`. The seal requires the matching source inventory, PASS in every required suite, deterministic assembled bytes, immutable predecessor arithmetic/server/camera checks, and relative dependency pins.

After sealing, run `node verify.cjs` again with no narrowed mode. Preserve its fresh receipt outside the seal. Run check-integrity.cjs after the full verification and verify the external evidence bundle's checksums. The final handoff reports both new check counts and inherited totals, distinguishing repeated suites from unique checks. Numerical comparisons inside a check group are not added again to the check count.

The old builder documents prefixed P1_PREDECESSOR_ and U1_PREDECESSOR_ are historical provenance. Current U1/P1 independent PASS is recorded in the sibling Opus audit, pinned by SOURCE_PINS.json. The controlling M4 prompt remains a pinned sibling document; it is not copied into the seal because it contains an absolute workspace path. All runtime paths and temporary receipts belong only in external evidence.
