# PORT NOTE v0.4.9 (2026-10-20): full stack and fraction stack from the old FVLT monodromy instrument

saphir's request: "we have lost the ability to use alpha in the old Monodromy instrument. I want to see the full stack coordinates. can you put the coordinate system into the new viewer?"
Source (frozen, read only): `cold audit fourier/MCOMB_FCA_M7_COMBINED_BCD_RHM_AF_v0_1_20261004/monodromy-31-linked-reduction.html` (sha256 b4cee4e3...e248): `buildFullStack` L7887, `computeVernier` L7365, `buildLiftFullStackSpecs` L5148 / `buildSelectedLiftFullStackSpecs` L5678, caches L8941-8976, fraction stack L9110-9260, travel marks L600-620 and L11702.

## 1. What the old full stack is
The point set: for every integer layer s and every integer shell position φ₃, both in {0, ..., B+1} (span = B+1), N = B+1−φ₃, and every tooth c of the centred m-comb, one point, the tooth

  z_c(s, φ₃) = n₆·N^α·exp(iπ(N·t₁ + c·t₂)·s/N)

of the comb at that state (the old code runs every point through `computeVernier`). The φ₃ = B+1 column has N = 0: no comb there (the old code skips it silently; here it is counted and labelled). Integer spins only. The old comment: the Archimedean arms are forced, not chosen, because n₃ = N = B+1−φ₃ ties radius and phase together along the φ₃ sweep.
Lattice and thinning (host rule, kept): gridCap = 58,081 = 241² for m ≤ 30, else max(400, ⌊58,081·30/m⌋); step 1 if (span+1)² ≤ gridCap, else ⌈span/√gridCap⌉, same step for s and φ₃. So the (s, φ₃) lattice is m-independent through m = 30 and bucketed by m above that; it never depends on φ₃, s or any other state. The old Plane draw is signature-cached; the old Clifford lift draws at most 12,000 heads (the host budget, less the current and rosette heads) chosen by `selectHeadIndices` (⌊i(L−1)/(max−1)⌋).

## 2. What the old fraction stack is (v0.8.7)
The current shell's row on a fraction lattice: s = j/q, j = 0 ... q·span, every tooth c, at the current N. q is the reduced denominator of the exact spin; at an integer spin, q is the shell's spread lattice q = m|t₂|/gcd(N or 2N, m|t₂|). Gated: integer shell, integer gearbox, q > 1, q ≤ 60; at most 4,000 heads, evenly selected; spread-zero columns (comb sum exactly 0) are bright. In the old instrument it was drawn only in the Clifford lift. This viewer already has it on the Clifford tab (`host-core/fraction-stack-core.js`, addendum 3).

## 3. Registers
- Full stack: the phase of every point, (N·t₁ + c·t₂)·s/N mod 2, is exact (integer arithmetic; the same k_c and phase as comb-core `teeth()`), so every phase factor is an exact root of unity. The amplitude n₆·N^α is an exact rational only when α is an integer (else in general irrational); it is computed in float64 as comb-numeric `compute()` does. The drawn coordinates are float64: drawing register.
- Fraction stack: certified exact phases on s = j/q (fraction-stack-core; integer shell, integer gearbox); drawn float64.
- Neither enters teeth, walk, orbits, readouts, cards or exports: display only.

## 4. Dependence
n₆, α (any exact value the viewer accepts, |α| ≤ 8, not only −1/0/+1), t₁, t₂ (rationals), m, the shell (n!, integer, CA presets: CA is integer mode with a preset B). Not on φ₃ or s (the stack is the whole lattice; φ₃ and s only move the current comb). Not on α_Tilt: α_Tilt weights the walk, the stack is made of teeth, so the stack ignores α_Tilt. In N∈ℚ mode the stack is still the integer lattice (shells only). The fraction stack depends on the current shell and s.

## 5. Where it goes in the new viewer
- Fourier (planar): Full stack = the planar points z_c on the canvas layer under the SVG, tooth colours, opacity 0.5 (host); the frame is fitted to include the stack. Fraction stack = the heads as planar teeth at the current N; they all lie on the current radius circle |z| = |ρ| (new: the old instrument did not draw it in the plane).
- Clifford: Full stack = the S³ lift of each point on its own leaf ρ_N = |n₆|·N^α (z₁ = a·e^{iπ(t₁s+f)}, z₂ = b·e^{−iπc·t₂s/N}, a = ρ_N/√(1+ρ_N²), b = 1/√(1+ρ_N²)), stereographic from x₄ = +1, as the old lift and as this viewer's tooth dots; the old 12,000-head budget less the m current teeth. For integer t₁ and s the cloud sits at azimuths {0, π} (the old "authoritative white cloud" is a planar page). Fraction stack: already present, unchanged.
- Hopf base: the stack has a natural image: each point's Hopf base point. In the host chart (w = W) this is fromAffine(z_c), the exact Hopf image of its lift (chart agreement). In the comb chart (w = W/ρ) the view divides by the current ρ; that is labelled. Fraction stack: all heads lie on the current latitude.
- Travel marks / coverage rings: they need the meridional sweep (slice / follow, γ rotation of the stack page), which this viewer does not have. Not ported.

## 7. Finding: where α is lost in the old Clifford-lift picture (read only; the frozen file is not edited)
The old data path keeps α. `buildFullStack` keys its cache on `state.alpha` (L7890) and `computeVernier` uses it (L7383–7385); the lift specs carry `alpha` (L5148, L5678), `liftStackExactCacheKey` includes it (L8941), and `liftToS3` (L4766) / `ContinuousRadialDisplayV1.liftToS3` (L5353) compute ρ_N = |n₆|·N^α from it. Run in Node (build/probe-old-lift-alpha.cjs), the old stack lift does change with α (max |projected point| 48.0 at α = −1, 2.41 at α = 0, 1.62 at α = +1, n₁ = 4, m = 2). What drops α is the display: the old page opened (Playwright, build/probe-old-page-alpha.cjs, log in build/_logs) with `state.cliffordLeafMode = 'sweep'` (rho label "arithmetic ρ=… retained · display η=≈0.25π · ρ_display=1"; one path that sets it at load is the embedded panel's `apply()` binding, L16283–16287; I did not establish which path ran). In sweep mode `renderClifford` (L11573–11576) replaces every point, stack included, by `S3LeafSweepDisplayV1.reprojectPoints` (L8202–8221), which keeps only the angles θ₁ = arg z₁, θ₂ = arg z₂ and puts the point on the display leaf T²_η (here ρ_display = 1). The radius, the only place α enters, is discarded by design ("phase-preserving η display copies"): the displayed stack had the same norms at α = −1, 0, +1 (median 1, max 2.414). So α is not lost in the arithmetic; the old picture normalises the radius by design while the leaf sweep is engaged. Turning the meridional sweep on (Slice) switches the leaf back to arithmetic (L12745–12747), which is why the stack picture "comes back a little"; its sweep copies are drawn grey at opacity ≤ 0.34 (L11706–11721), hence dark. A second, smaller effect, outside sweep mode: `prepareCameraScreen` (L5260) fits the frame to all finite points, so at α = −1 the far stack points (|x| up to 48) shrink the guide to about 20 px (fit 95 → 8 at 640×480). The new viewer has neither: each stack point sits on its own leaf ρ_N, and the Clifford frame is fitted to the guide, the current leaf and the current teeth, not to the stack.
